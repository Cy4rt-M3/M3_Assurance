1. Introduction and Purpose
Module 3: Assurance is the compliance and evidence verification engine of the CyBreach autonomous cybersecurity
platform. It consumes validated verdicts from Module 2 (The Validator), maps them to regulatory controls across
multiple global compliance frameworks, calculates the composite Resilience Score, and generates comprehensive
compliance reports. The fundamental hard rule governing Module 3 is: never mark a control as met without linked
validated evidence. Every compliance claim must trace to an immutable evidence event chain that originates from
Module 1 (Strike Engine) and passes through Module 2 validation.
Assurance transforms raw security validation data into actionable compliance intelligence. Where Module 1 produces
evidence events and Module 2 validates detection effectiveness, Module 3 connects these technical results to the
regulatory and business context that organizations need for audits, board reporting, and regulatory submissions. By
automating the control mapping and evidence aggregation process, Assurance eliminates the manual spreadsheet
work that consumes 60-70% of compliance team effort in traditional security programs.
The module supports multiple global regulatory frameworks simultaneously, including NIST Cybersecurity
Framework 2.0, ISO 27001:2022, PCI-DSS 4.0, GDPR, SOC 2 Type II, HIPAA, and the NIS2 Directive. A single
evidence event chain can satisfy controls across all applicable frameworks, dramatically reducing redundant testing
and documentation effort. Regional variants (India, EU, US, UK, Middle East, Asia-Pacific) extend the global
frameworks with location-specific requirements.
Note: The hard rule: never mark a control met without linked validated evidence. If Module 2 produces a
verdict of Missed or No Data for a detection that maps to a control, that control must be marked as Not Met
regardless of any other evidence.
2. Build Model: Zero Interdependency
Module 3 follows the same zero-interdependency model as all CyBreach modules. It publishes its contracts
(compliance_report schema, resilience_score schema, control_mapping schema, gap_analysis schema) on day zero
and consumes Module 2 published verdict contracts as frozen fixtures. It does not call Module 2 at build time; instead,
all verdict data comes from frozen fixtures and mock events that conform to Module 2 published contracts.
The frozen fixture approach means that Module 3 developers can work independently from Module 2 developers.
Fixtures include sample verdict events for Detected, Missed, Partial, and No Data outcomes, along with the associated
evidence event metadata. These fixtures are versioned in the same schema registry as the live contracts, ensuring that
when integration testing begins, the transition from mock to real data is seamless.
Module 3 also publishes contracts that Module 4 (Arena) consumes, including the resilience_score event and the
compliance_report_available event. These contracts are frozen before development begins, and Module 4 builds
against these frozen contracts using mock fixtures. This bidirectional contract publishing ensures that all four modules
can be developed in parallel without any runtime dependencies during the build phase.

3.1 Control Mapping Engine
The Control Mapping Engine maps MITRE ATT&CK; techniques and Module 2 detection verdicts to regulatory controls
across multiple global frameworks. It maintains a mapping table that connects each ATT&CK; technique to the specific
controls it satisfies in each supported framework. When Module 2 produces a verdict (Detected, Missed, Partial, No
Data) for a technique, the Control Mapping Engine looks up all controls that technique maps to and updates the control
status accordingly. A control is only marked as Met when all techniques that map to it have a Detected verdict with
linked validated evidence.

@app.post("/api/v1/map-controls")
async def map_controls(req: ControlMappingRequest):
verdict = await verdict_store.get(req.verdict_id)
if not verdict:
raise HTTPException(404, "Verdict not found")
# Get all control mappings for the technique
mappings = await mapping_store.get_by_technique(
verdict.technique_id, req.framework_ids)
control_statuses = {}
for mapping in mappings:
# A control is Met only if verdict is Detected
if verdict.outcome == "Detected":
existing = control_statuses.get(mapping.control_id)
if existing != "Met":
control_statuses[mapping.control_id] = "Met"
# Link evidence to control
await evidence_link.create(
control_id=mapping.control_id,
verdict_id=verdict.verdict_id,
evidence_hash=verdict.evidence_hash)
elif verdict.outcome in ("Missed", "No Data"):
control_statuses[mapping.control_id] = "Not Met"
else:
control_statuses[mapping.control_id] = "Partial"
# Calculate coverage percentage
total = len(control_statuses)
met_count = sum(1 for s in control_statuses.values() if s == "Met")
coverage = (met_count / total * 100) if total > 0 else 0
return {"control_statuses": control_statuses,
"coverage_pct": round(coverage, 1),
"framework_ids": req.framework_ids}

3.2 Evidence Aggregator
The Evidence Aggregator collects and deduplicates evidence events from the full chain (Module 1 actions and Module
2 verdicts), maintaining evidence lineage from the original simulated action through detection validation to compliance
mapping. It ensures that each piece of evidence is counted exactly once, even when it satisfies controls across
multiple frameworks. The aggregator builds an evidence graph that traces the complete chain: simulated action
(Module 1) produces evidence event, evidence event is validated by detection (Module 2), validated evidence maps to
controls (Module 3).

The Resilience Score Calculator computes the composite Resilience Score from three weighted components: Control
Coverage (40%), Detection Effectiveness (35%), and Evidence Completeness (25%). The score ranges from 0 to 100,
with bands: 0-40 Critical, 41-60 At Risk, 61-75 Moderate, 76-90 Strong, 91-100 Resilient. Each component is
calculated independently and then combined using the weighted formula.
 @app.post("/api/v1/calculate-score")
async def calculate_score(req: ScoreRequest):
# Control Coverage (40%)
controls = await control_status_store.get_by_engagement(
req.engagement_id, req.framework_ids)
total_controls = len(controls)
met_controls = sum(1 for c in controls.values() if c == "Met")
coverage_score = (met_controls / total_controls * 100) if total_controls > 0 else 0
# Detection Effectiveness (35%)
verdicts = await verdict_store.get_by_engagement(req.engagement_id)
total_detections = len(verdicts)
detected = sum(1 for v in verdicts if v.outcome == "Detected")
detection_score = (detected / total_detections * 100) if total_detections > 0 else 0
# Evidence Completeness (25%)
evidence = await evidence_link_store.get_by_engagement(req.engagement_id)
expected_events = await evidence_event_store.count_by_engagement(req.engagement_id)
linked_events = len(set(e.evidence_hash for e in evidence))
evidence_score = (linked_events / expected_events * 100) if expected_events > 0 else 0
# Composite score
composite = (coverage_score * 0.40 +
detection_score * 0.35 +
evidence_score * 0.25)
# Determine band
if composite <= 40: band = "Critical"
elif composite <= 60: band = "At Risk"
elif composite <= 75: band = "Moderate"
elif composite <= 90: band = "Strong"
else: band = "Resilient"
return {"composite_score": round(composite, 1),
"coverage_score": round(coverage_score, 1),
"detection_score": round(detection_score, 1),
"evidence_score": round(evidence_score, 1),
"band": band}
3.5 Gap Analyzer
The Gap Analyzer identifies uncovered controls, missed detections, and evidence gaps with specific remediation
recommendations. It produces a prioritized gap list sorted by risk impact, showing which controls are not met, which
detections are missing, and what evidence is incomplete. For each gap, it provides a recommended remediation action
such as deploying a specific detection rule, adding a monitoring source, or implementing a compensating control.
3.6 Framework Registry
The Framework Registry manages regulatory framework definitions, control catalogs, and cross-walk mappings
between frameworks. It stores the complete control hierarchy for each framework (framework, category, control,
sub-control) and the mapping between ATT&CK; techniques and controls. It also maintains cross-walk mappings that
show how a single control in one framework maps to equivalent controls in other frameworks, enabling organizations
to satisfy multiple compliance requirements with a single evidence chain.

4.1 NIST Cybersecurity Framework 2.0
The NIST Cybersecurity Framework (CSF) 2.0, published in February 2024, is the most widely adopted cybersecurity
framework globally. It organizes cybersecurity activities into six core functions: Govern, Identify, Protect, Detect,
Respond, and Recover. The Govern function is new in version 2.0 and emphasizes organizational context, risk
management strategy, and supply chain risk management. The framework contains 22 categories and 106
subcategories that provide granular guidance for cybersecurity implementation.
For CyBreach mapping, the Detect and Respond functions are most directly relevant. The Detect function (DE) covers
anomalies and events (DE.AE), continuous monitoring (DE.CM), and detection processes (DE.DP). The Respond
function (RS) covers response planning (RS.RP), communications (RS.CO), analysis (RS.AN), mitigation (RS.MI), and
improvements (RS.IM). Each ATT&CK; technique simulated by Module 1 and validated by Module 2 maps to specific
Detect and Respond subcategories, providing direct evidence of detection capability and response readiness.

The composite score formula is: Score = (Coverage x 0.40) + (Detection x 0.35) + (Evidence x 0.25). Each component

9. Credit Logic
Compliance report generation costs credits from the Module 4 wallet. The credit costs are: single-framework report
costs 5 credits, multi-framework report (up to 3 frameworks) costs 10 credits, comprehensive report (all frameworks
plus regional variants) costs 25 credits, and re-assessment score calculation costs 2 credits. If a report generation fails
due to insufficient evidence, the credits are automatically refunded. Module 3 sends a credit debit request to the
credit_debit_request message bus topic and awaits confirmation from Module 4 before generating the report.

10. Unique Selling Points
Multi-Framework Compliance from Single Evidence Chain: Module 3 enables organizations to validate compliance
across multiple regulatory frameworks simultaneously using a single evidence chain from the CyBreach platform. A
single engagement that simulates ransomware techniques can provide evidence for NIST CSF 2.0, ISO 27001,
PCI-DSS, GDPR, SOC 2, HIPAA, and NIS2 controls all at once. This eliminates the redundant testing and
documentation that consumes the majority of compliance team effort in traditional security programs, reducing
compliance costs by an estimated 60-70%.
Automated Cross-Walk Mapping: The Cross-Walk Engine automatically identifies equivalent controls across different
frameworks, showing that satisfying a control in one framework also satisfies related controls in others. This
eliminates the manual mapping effort that compliance teams spend weeks on during audit preparation. The
cross-walk also highlights gaps where a control satisfied in one framework does not have an equivalent in another,
ensuring no compliance requirements are overlooked.
Quantified Resilience Score: The Resilience Score provides a single, objective metric that quantifies cybersecurity
resilience based on three weighted components: control coverage, detection effectiveness, and evidence
completeness. Unlike subjective compliance ratings, the Resilience Score is calculated from concrete,
evidence-backed measurements that are fully auditable and reproducible. The score enables meaningful comparison
across organizations, industries, and time periods.
Evidence-Backed Control Verification: Every control status in Module 3 traces back to validated evidence events from
Module 1 and Module 2. The hard rule (never mark a control met without linked validated evidence) ensures that
compliance reports reflect actual security capability, not just policy documentation. This evidence-backed approach
transforms compliance from a checkbox exercise into a meaningful security validation.
Global Regulatory Coverage: Module 3 supports seven major global regulatory frameworks and six regional variants
out of the box, covering the compliance requirements of organizations operating in virtually any market worldwide.
